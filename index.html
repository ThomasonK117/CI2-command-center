v0.2 — The Offline App

Architecture decision: the Project is the container. The A3 is one view of project knowledge, not the entire application.

What changed: the shell is now installable as a Progressive Web App, with a manifest and service worker that cache the application shell for offline use after the first successful load.

Why offline-first: the app shell can remain usable when connectivity drops. Prototype project data still uses browser-local storage while we validate the workflow; IndexedDB is the next storage upgrade.

Next lesson: after your real A3 arrives, we will map its information architecture to this prototype and refactor the shell around your actual CI² process.
